# Библиотека компонентов REPPY

Единственное место для изменения UI — папка `app/ui`. Экраны используют её компоненты; нативные HTML/SVG-элементы создаются внутри библиотеки. Поведение тренировок, абонементов и маршрутов остаётся в модулях приложения.

При любом изменении интерфейса и добавлении нового компонента действуют [постоянные правила дизайна](design-principles.md), кратко продублированные в корневом `AGENTS.md`. Одна поверхность карточки, минимум декоративных контуров, подходы строками; общие высоты контролов 44 / 48 / 56 px, CTA лендинга 60 px.

Кнопки всегда имеют различимый фон области нажатия (`--button-bg`), включая иконочные и вторичные. На светлой странице `--surface-2` слишком близок к фону для вторичных действий. Между отдельными карточками — `--card-list-gap` (24 px), внутри — компактные интервалы. Названия упражнений используют общий `--exercise-title-font-size` во всех режимах.

Неактивные табы нижней мобильной навигации прозрачны внутри полностью скруглённой плавающей капсулы; активный таб образует внутреннюю концентрическую капсулу. Логотип-кнопка в шапке тоже без подложки в обеих темах; фокус сохраняется. Это исключения из правила фоновой заливки кнопки. Экран загрузки использует ровный чёрный фон без градиентов.

## Точки изменения

| Что меняем | Где |
| --- | --- |
| Цвета обеих тем, шрифты, размеры, отступы, скругления | `app/ui/tokens.css` |
| Любые визуальные правила, варианты, адаптивность, hover/focus/disabled | `app/ui/styles.css` |
| Базовые визуальные элементы, типографика, списки, изображения, SVG | `app/ui/elements.tsx` |
| Кнопки, поля, переключатель | `app/ui/controls.tsx` |
| Заголовок секции, поле с подписью, бейдж, прогресс, строка списка, кнопка навигации | `app/ui/patterns.tsx` |
| Логотипы, маскот и иллюстрация результата | `app/ui/assets.ts` |
| Импорт компонентов и доступ к библиотеке | `app/ui/index.ts` |
| Состав библиотеки, который выводится в дизайн-ките | `app/ui/catalog.ts` |

В той же папке находятся общие составные компоненты: AppShell, PageHeader, ModalFrame, ConfirmationModal, EmptyState, Avatar, Icon, WorkoutScheduleFields/DatePickerField, MonthDatePicker, PlanExerciseCard, ActiveExerciseCard, ReadOnlyExerciseList, ExerciseInstructionModal, ProgressChart и AppStatusBanner. Для изменения разметки конкретного составного компонента редактируем его модуль в этой папке; для изменения его вида — общий файл стилей.

`app/globals.css` только подключает `tokens.css` и `styles.css`. Отдельных стилевых файлов на экранах нет. Разделы внутри `styles.css` сохраняют исходный порядок каскада; последние разделы задают общие состояния и примеры библиотеки.

## Общие настройки

В начале `tokens.css` доступны масштабы (по умолчанию 1):

- `--ui-font-scale` — все уровни текстовой шкалы;
- `--ui-radius-scale` — скругления;
- `--ui-space-scale` — отступы и расстояния;
- `--ui-control-height-scale`, `--ui-control-width-scale` — размеры контролов, сохраняя различия контекстов;
- `--ui-icon-scale` — размеры иконок.

Семантические роли темы: `--lime`, `--text-primary`, `--text-secondary`, `--muted`, `--surface`, `--ui-outline`, `--error-color`, роли бейджей. Основное семейство — `--app-font-sans`, числа — `--app-font-mono`, кнопки — `--button-font-size`. Явные размеры ActionButton: `--control-height-small/medium/large`, `--control-radius`, `--control-padding`.

Шкалы `--font-size-*`, `--font-weight-*`, `--radius-*`, `--space-*`, `--size-*` сохраняют исходные значения. `--palette-*-rgb` хранит каналы цвета; зависимые цвета и прозрачные оттенки используют их автоматически. Для изменения только одного вида элемента добавляем семантическую роль и используем её во всех вариантах этого элемента.

Нативные теги и ref сохраняются, дополнительных DOM-обёрток нет. Семантические элементы (формы, подписи полей, заголовки, списки, даты, SVG) остаются семантическими. Общие компоненты имеют `data-ui-element`/`data-ui-control` для проверки и диагностики. Динамический процент прогресса и путь маски иконки задаются только внутри библиотечных компонентов; геометрия графика остаётся данными графика.

`ModalFrame` и `ConfirmationModal` по умолчанию добавляют запись истории, чтобы Back закрывал окно. Подтверждение несохранённой формы использует `trackHistory={false}`: навигационный guard сам восстанавливает исходную запись и повторяет выбранное перемещение после подтверждения. Это сохраняет будущие записи Forward при отмене выхода.

Защита несохранённой формы регистрируется до первого отображения, включая восстановленный черновик после reload. Окно инструкции блокирует изменение текста/файла на время сохранения, но его можно закрыть; поздний результат закрытого окна не изменяет план, не очищает новый черновик и не закрывает повторно открытое окно. После ошибки поля и повторное сохранение снова доступны.

Каждый сохранённый маршрут изолирован существующим `AppErrorBoundary`: ошибка экрана не размонтирует оболочку, контроллер аккаунта, очередь неподтверждённых команд или другие сохранённые формы. В памяти остаются не более 12 недавно открытых маршрутов, чтобы скрытые экраны не росли без ограничения; черновики форм сохраняются отдельно. Ошибочный маршрут показывает действие «Вернуться на главную» вне оболочки, чтобы оно работало и при заблокированном модальным слоем экране. Оно сохраняет очередь команд и удаляет сбойный маршрут из кеша. На экране доступен локальный журнал ошибки. Корневой boundary остаётся последним резервом для ошибок вне маршрутов.

Состояние ошибки хранится отдельно у каждого сохранённого маршрута: Back/Forward не скрывает восстановление ранее упавшего экрана. Если сама главная упала, действие восстановления повторно монтирует только её boundary, даже без смены URL; повторная ошибка снова оставляет доступное восстановление. Экран использует общий `ModalLayer` с `trackHistory={false}` и `closeOnHistoryBack={false}`: фокус переходит к действиям, Tab остаётся внутри, Escape возвращает на главную, а закрытая оболочка временно становится inert. Browser Back/Forward продолжает обычную навигацию между экранами, не вызывает действие восстановления. Здоровые сохранённые формы не сбрасываются; стандартные модалки сохраняют закрытие по Back.

Рабочие маршруты импортируются сразу при запуске. Не возвращай `React.lazy` для экранов без схемы сохранения старых JS-файлов между релизами: GitHub Pages заменяет артефакт целиком, а открытая вкладка может запросить удалённый файл маршрута после публикации.

Экран восстановления центрирует содержимое только при достаточной высоте. На коротком экране начало сообщения и все действия остаются достижимыми прокруткой, без смещения выше начала scroll area. Профиль и экран неподключённого профиля показывают ожидание выхода, блокируют повторное нажатие и выводят ошибку через FormError; ошибка не считается успешным выходом, повтор остаётся доступен.

После ошибки завершения Telegram redirect экран входа предлагает повторить текущую попытку либо начать вход заново. Успешно обменянный OAuth-код повторно не отправляется: его результат хранится только в памяти текущей страницы до подтверждения входа. Callback удаляется после успеха или явного нового входа; после reload уже использованного кода доступен новый вход. Ожидание блокирует оба действия; ошибки используют FormError и обычные размеры ActionButton.

В редакторе плана кнопка добавления упражнения находится в заголовке «Упражнения», в обычном потоке страницы. Она прокручивается вместе с заголовком и не перекрывает карточки или поля подходов. Размеры, цвета и иконка используют существующие общие токены; фиксированная плавающая кнопка для этого экрана не используется.

## Страница компонентов

Профиль тренера → «Открыть дизайн-кит», маршрут `#/trainer/design-kit`. Страница показывает реальные контролы, карточку упражнения, системные состояния, модальное окно, поля, бейджи, прогресс, аватары, строки списков, навигацию и уведомления. Состав библиотеки строится из реальных ссылок на компоненты `UI_COMPONENTS`, а примеры не записывают рабочие данные.

## Защита от обхода библиотеки

`tests/component-library.test.mjs` проверяет весь `app` рекурсивно:

- нет нативной HTML/SVG-разметки вне библиотечных примитивов;
- нет inline-оформления на экранах;
- CSS находится только в библиотеке, а все ссылки на токены определены;
- повторяющиеся паттерны и общие графические ресурсы используют библиотеку.

При добавлении элемента сначала выбираем существующий компонент. Новый компонент помещаем в `app/ui`, регистрируем в `catalog.ts` и добавляем его показательный пример в дизайн-кит. Не создаём локальный вариант той же карточки, кнопки, поля или статуса на отдельном экране.

## Проверка и публикация

`npm test`, `npm run lint`, `npm run typecheck`, `npm run test:e2e`. Браузерные проверки подтверждают, что общие настройки меняют реальные экраны и дизайн-кит, а клавиатурные сценарии, обе темы и мобильная ширина работают.

`NoteDayCard` — общая плитка дневника с отдельным скроллом и действиями списков; состояния показаны в дизайн-ките. При пяти вкладках мобильное меню показывает подпись выбранного таба и иконки остальных, сохраняя доступные названия, фокус и размеры кнопок. Поведение и хранение описаны в [заметках тренера](trainer-notes.md).

Публикация — push в `main`, затем успешный workflow `Deploy REPPY to GitHub Pages`. Явно запрошенная ранняя публикация через `[publish-now]` выполняет lint, typecheck и сборку, пока полный набор проверок продолжается.

`SegmentedControl` — общий переключатель разделов с доступными кнопками и выбранным состоянием; пример находится в дизайн-ките. В дневнике интервал сетки использует `--notes-grid-gap`, шрифт — `--notes-editor-font-size`.

Профиль использует общую оболочку и одну прокрутку `.page-wrap`, как остальные табы. Нижняя капсула закреплена с отступом `max(4px, safe-area-inset-bottom)`; под ней резервируется место в скролле. Анимация входа применяется к main активного сохранённого маршрута и отключается при reduced motion. Поля заметок имеют 16 px для предотвращения Safari focus zoom без запрета ручного масштабирования. Прогресс использует отдельные карточки с `--card-list-gap`.
