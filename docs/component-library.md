# Библиотека компонентов REPPY

Общие контролы используются на всех экранах тренера, ученика, авторизации и лендинга. Дизайн-кит доступен в настройках тренера: «Открыть дизайн-кит», маршрут `#/trainer/design-kit`.

## Где менять оформление

- `app/styles/00-design-tokens.css` — единый источник цветов, шрифтов, размеров, отступов и скруглений. Семантические роли тёмной и светлой тем находятся в конце файла.
- `app/ui-controls.tsx` — Button, ActionButton, IconButton, Input, TextField, Select, Textarea, Switch и FormError. Сохраняют нативные атрибуты, события и ref. У Button по умолчанию `type="button"`; отправку формы нужно задавать явно.
- `app/styles/14-component-library.css` — размеры small/medium/large, фокус, неактивные поля, ошибки и дополнительные примеры дизайн-кита.
- `app/styles/06-shared-controls.css` и существующие классы `.primary-button`, `.wide-secondary`, `.danger-button`, `.text-input` — общие стили вариантов. Контекстные размеры сохранены, чтобы миграция не меняла экраны.
- `app/trainer-design-kit.tsx` — живая страница библиотеки. Показывает настоящие контролы, выбор даты, состояния синхронизации, ConfirmationModal и ReadOnlyExerciseList; примеры используют локальные данные и не меняют рабочие тренировки.

Общие составные компоненты: AppShell, PageHeader/RoutePageHeader, ModalFrame, ConfirmationModal, EmptyState, Avatar, Icon, WorkoutScheduleFields/DatePickerField, MonthDatePicker, WorkoutExerciseCard, ReadOnlyExerciseList и AppStatusBanner. Их поведение меняется в соответствующем модуле, оформление — в общих стилях и токенах.

## Правила следующих изменений

Нативные `button/input/select/textarea` допустимы только внутри `ui-controls.tsx`. Для нового экрана сначала используем существующий компонент; повторяющуюся комбинацию выделяем в общий компонент и показываем в дизайн-ките.

Цвета задаём семантическими ролями (`--lime`, `--text-primary`, `--muted`, `--surface`, `--ui-outline`), а при необходимости добавляем роль в обе темы. Токены `--palette-*` и `--tint-*` сохраняют исходную палитру, включая иллюстративный лендинг. Не следует менять каждый оттенок отдельно для обновления темы: сначала выбираем роли и их потребителей.

Размеры явных вариантов ActionButton задаются `--control-height-small/medium/large`, скругление — `--control-radius`, горизонтальный отступ — `--control-padding`. Шрифт приложения — `--app-font-sans`, числа — `--app-font-mono`, кнопки — `--button-font-size`. Токены `--font-size-*`, `--font-weight-*`, `--radius-*`, `--space-*`, `--size-*` — исходные шкалы; менять их следует осознанно, так как значение может использоваться в разных компонентах. Для изменения только одного вида контрола добавляем семантический токен и переводим все его варианты на этот токен.

Ширины контейнеров, сетки, брейкпоинты и пропорции иллюстраций остаются в стилях экранов. Динамические проценты прогресса и пути SVG остаются в компонентах.

## Проверка и публикация

`npm test`, `npm run lint`, `npm run typecheck`, `npm run test:e2e`. Тест библиотеки проверяет, что изменение токена влияет на настоящий экран и дизайн-кит, доступность контролов и отсутствие горизонтального переполнения в обеих темах.

Публикация — push в `main`, затем успешный workflow `Deploy REPPY to GitHub Pages`. Изменения общих компонентов автоматически применяются к странице библиотеки и всем потребителям.
