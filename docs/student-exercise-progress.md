# ТЗ: Прогрессия ученика по упражнениям

Статус: реализовано в отдельной ветке; готово к просмотру перед слиянием.
Дата: 8 сентября 2026 года.
Ветка: `codex/student-exercise-progress`, создана от `main`.

## Задача

Тренер хочет видеть сводную таблицу результатов конкретного ученика, не открывая по очереди завершённые тренировки. Основные вопросы: «Что делали в прошлый раз?», «Как менялись вес и повторения?», «Какие были подходы и комментарии?».

## Предлагаемый формат

Два уровня: сводка упражнений ученика → история выбранного упражнения. На экране упражнения по умолчанию открыта таблица подходов; рядом переключатель «График». Таблица показывает точные результаты, график помогает быстро увидеть изменение одной выбранной величины во времени.

Не сводить прогресс к одному проценту или оценке: 80 кг × 8 и 85 кг × 5 — разные результаты, по одному весу нельзя объявлять второй лучше. Показывать факты и единицы измерения, оставляя интерпретацию тренеру.

## 1. Вход и навигация

- В профиле ученика, сразу после заголовка, добавить заметный пункт «Прогресс по упражнениям» с количеством упражнений с результатами.
- Открывать сводку только выбранного ученика; его имя постоянно видно в заголовке.
- В результате завершённой тренировки добавить у каждого упражнения действие «История упражнения», ведущее сразу к его прогрессии для этого ученика.
- Новые hash-маршруты: `#/trainer/clients/:studentId/progress` и `#/trainer/clients/:studentId/progress/:exerciseId`. Вариант измерения передавать параметрами `loadMode` и `measureType`.
- Период, поиск, вид и метрику хранить в параметрах маршрута. «Назад» возвращает к предыдущему экрану с сохранённым выбором; прямая ссылка и обновление страницы работают. При отсутствии истории браузера использовать профиль/сводку как запасной маршрут.
- Отдельный раздел в главной навигации не нужен. Первая версия предназначена для тренера; кабинет ученика расширим отдельно.

## 2. Сводка упражнений ученика

Поиск по названию без учёта регистра, периоды «30 дней», «90 дней», «Всё время»; по умолчанию — 90 дней. Период распространяется на список и детали. В список входят упражнения хотя бы с одним валидным выполненным подходом за период.

На широком экране — таблица, на телефоне — компактные строки с теми же данными:

| Упражнение | Последний результат | Когда | Занятий за период |
| --- | --- | --- | --- |
| Жим лёжа | 80 кг × 8 / 8 / 7 · 3 подхода | 07.09.2026 | 8 |
| Подтягивания | 8 / 7 / 6 повт. · 3 подхода | 05.09.2026 | 6 |
| Планка | 45 / 45 / 40 сек. · 3 подхода | 05.09.2026 | 6 |

Примеры иллюстративные, не реальные данные ученика. При разных весах писать вес у каждого подхода. В сводке показывать максимум три подхода и «ещё N»; полный набор доступен в деталях. Последний результат — из последнего занятия в выбранном периоде, а не максимальный за историю.

Сортировка по последнему выполнению, новые сверху; при равной дате — по названию. Нажатие на строку открывает историю упражнения. Для одинакового упражнения с разными режимами нагрузки/измерения показывать отдельные строки с явными подписями.

## 3. История упражнения: основной экран

Порядок блоков:

1. Назад, имя ученика, название упражнения с выбором другого упражнения на месте. Выбор сохраняет период, вид и метрику; подписи режима нужны только для различения вариантов одного упражнения.
2. Период и число занятий с выполненными подходами.
3. Переключатель «Таблица / График», по умолчанию «Таблица». Рядом — число занятий.
4. Выбранный вид. Отдельной карточки последнего результата нет: он уже показан первой строкой таблицы или выбранной точкой графика.

### Таблица

Одна строка — одно завершённое занятие. Новые занятия сверху. Колонки: дата и результат. Нажатие на дату открывает тренировку. Название тренировки, время, план и комментарии находятся в «Подробнее»; при нескольких занятиях в один день время также видно рядом с датой.

В основном виде показывать только выполненные подходы. Одинаковый вес записывать один раз: `80 кг × 8 / 8 / 7 повт.`. При частичном выполнении добавить одну подпись «Выполнено 2 из 3». Номера подходов, пропуски и некорректные записи сохраняются в подробностях.

| Дата | Результат |
| --- | --- |
| 07.09.2026 | 80 кг × 8 / 8 / 7 повт. |
| 31.08.2026 | 77,5 кг × 8 / 8 / 8 повт. |
| 24.08.2026 | 75 кг × 8 / 8 повт. · Выполнено 2 из 3 |

Не создавать отдельные обязательные колонки для каждого номера подхода: их количество меняется. На телефоне дата и результат располагаются друг под другом, подходы переносятся по строкам, горизонтальная прокрутка страницы не нужна. В подробностях сохранять номера подходов, чтобы пропуски были понятны.

Раскрытие занятия показывает план рядом с фактом по каждому подходу, заметку тренера из снимка упражнения, комментарий и самочувствие ученика из сессии. Комментарий подписывать «К тренировке»: отдельного комментария ученика к упражнению сейчас нет. Полная тренировка открывается существующим экраном результата.

Показывать первые 20 занятий, затем «Показать ещё» порциями по 20. График и сводные значения всегда считают весь выбранный период.

### График

Ось X — фактическая дата завершения занятия, расстояния соответствуют времени. Ось Y — одна выбранная метрика с единицами, без второй шкалы. Точки идут от старых к новым. Одна точка соответствует одному занятию, несколько занятий в день остаются отдельными точками; в деталях видны время и название тренировки.

| Режим упражнения | Метрика по умолчанию | Дополнительная метрика |
| --- | --- | --- |
| Внешний вес, повторения | Максимальный вес подхода, кг | Сумма повторений |
| Свой вес, повторения | Максимум повторений в подходе | Сумма повторений |
| Время | Максимальная длительность подхода, сек. | Сумма времени, сек. |

Метрики рассчитываются только по выполненным валидным подходам. Метрика переключается двумя кнопками за одно нажатие. При выборе точки показывать дату, значение и выполненные подходы с весом и повторениями; план, комментарии и переход к тренировке находятся в «Подробнее». Помимо выбора точки, доступны стрелки предыдущего и следующего занятия, в том числе для близких и совпадающих точек. Не повторять дату и результаты в дополнительных карточках и списках.

Не называть максимум веса «ростом силы», не добавлять автоматические оценки «лучше/хуже». Для упражнений на время с внешним весом график показывает время, вес остаётся в деталях подходов. Для собственного веса масса из профиля не участвует в вычислениях.

При одной точке показать её и текст «Для динамики нужно ещё одно занятие». Не добавлять нулевые значения в дни без занятий. Выбор точки доступен касанием и клавиатурой, без обязательного наведения мышью; таблица предоставляет те же исходные данные. Цвет не должен быть единственным носителем смысла.

## 4. Данные и правила расчёта

Текущая модель уже содержит `WorkoutSession`, `workoutSnapshot`, `results` и `completedAt`. Для первой версии достаточно вычисляемого представления; новые сохранённые сущности, миграция и изменение repository-контракта не нужны.

1. Выбирать сессии по `session.studentId` и наличию валидного `completedAt`. Не брать запланированные назначения и незавершённые сессии.
2. Источник состава и метаданных — исключительно `session.workoutSnapshot`. Изменение/удаление шаблона не меняет историю упражнения.
3. Важное различие идентификаторов: `SetResult.exerciseId` ссылается на `WorkoutExercise.id` внутри снимка. Сначала связать результат с этим экземпляром, затем группировать между сессиями по `WorkoutExercise.exerciseId` из справочника.
4. Ключ группы: `studentId + exerciseId + loadMode + measureType`. Не объединять по названию. Разные упражнения с похожими названиями не смешиваются. Заголовок брать из самого нового завершённого снимка группы за всю историю, независимо от периода; исторические подписи в раскрытии — из конкретной сессии.
5. Если упражнение встречается в занятии дважды в одном режиме, оставить одну строку/точку занятия, но показать два блока подходов в порядке снимка. Метрики считают оба блока, число занятий не удваивается.
6. В расчёты входят только `completed === true`, конечное положительное `actualReps` и, для внешнего веса, конечное неотрицательное `actualWeight`. Ноль кг допустим. Для повторений и секунд использовать `actualReps`: при `measureType === 'duration'` это поле хранит секунды.
7. В подробностях незавершённый подход показывать как «Не выполнен», не выдавая предзаполненные из плана числа за факт. Ошибочные завершённые данные показывать как «Некорректные данные», исключая из метрик. Основная строка показывает только выполненные валидные результаты и общий статус частичного выполнения. Несвязанные со снимком результаты не угадывать по имени и не учитывать.
8. Занятие без единого валидного выполненного подхода группы не входит в её сводку, историю или график. Частично выполненное — входит с явными пропусками. «Выполнено/всего» означает число валидных выполненных подходов относительно всех предусмотренных снимком подходов данной группы.
9. Дата истории — `completedAt`, не дата назначения. Для 30/90 дней использовать календарные дни в текущем часовом поясе браузера: от начала дня N−1 дней назад до текущего момента включительно. Сортировать по timestamp, при равенстве — по `session.id` для стабильного порядка.
10. Записи тренера и ученика учитываются одинаково. После завершения занятия данные появляются сразу; удаление сессии существующим действием удаляет её вклад в прогрессию. Сам экран прогрессии ничего не меняет и не сохраняет в сессиях.

## 5. Состояния и ограничения

- Нет результатов за всю историю: «Здесь появится прогресс по упражнениям после первой завершённой тренировки».
- История есть, но выбранный период пуст: «За этот период нет результатов» и действие «Показать всё время».
- Поиск ничего не нашёл: «Упражнения не найдены» и сброс поиска.
- Неизвестный ученик, упражнение или режим в прямой ссылке: понятное пустое состояние/экран отсутствия данных с возвратом к ученикам или сводке. Не показывать данные другого ученика.
- Длинные названия, дробные веса, разное количество подходов и несколько занятий в день должны оставаться читаемыми на экране шириной 360 px.
- Данные пока доступны в одном браузере через существующий repository и `localStorage`. Backend и настоящая авторизация остаются отдельными задачами из backlog.

## 6. Объём первой реализации

Включить сводку, историю подходов, раскрытие плана/факта, простой график, периоды, поиск, два входа и состояния без данных. Разрабатывать последовательно:

1. Чистые функции агрегации в отдельном `app/exercise-progress.ts` и предметные unit-тесты.
2. Маршруты, сводка и адаптивная таблица истории; это первый проверяемый результат для тренера.
3. График и доступное управление точками, использующие те же агрегаты.
4. E2E, проверки проекта, ручная проверка на телефоне и компьютере.

Отложить: расчёт 1ПМ, тоннаж, личные рекорды и рейтинги прогресса, сравнение учеников, автоматическое назначение нагрузки, экспорт, пользовательский диапазон дат, раздел прогрессии ученика и подсказку «прошлый результат» во время выполнения. Разминочные и рабочие подходы сейчас не различаются, поэтому все отмеченные подходы участвуют одинаково.

## 7. Приёмка

- [ ] Из профиля выбранного ученика история упражнения доступна за два нажатия; из результата тренировки — за одно.
- [ ] Одно упражнение из разных шаблонов и персональных версий собирается вместе; результаты другого ученика не попадают в выборку.
- [ ] Повтор упражнения в одной сессии даёт одну строку и одну точку с отдельными блоками подходов.
- [ ] Таблица точно воспроизводит вес, повторения/секунды, порядок и пропуски подходов; раскрытие показывает план отдельно от факта.
- [ ] Внешний вес, собственный вес и время имеют правильные единицы и не смешиваются в одной серии.
- [ ] Предзаполненные, незавершённые и некорректные результаты не попадают в метрики; ноль кг не считается отсутствием данных.
- [ ] На примере 80 кг × 8 → 85 кг × 5 график веса показывает 80 → 85, детали сохраняют 8 → 5, автоматической оценки прогресса нет.
- [ ] Периоды одинаково фильтруют таблицу, график, последний результат и число занятий; «Показать ещё» не меняет агрегаты.
- [ ] Покрыты границы периода, две сессии в один день, пустая история, один результат и пустой поиск.
- [ ] Изменение/удаление исходного шаблона не меняет историю; завершение новой сессии добавляет результат, удаление сессии убирает его.
- [ ] Прямые ссылки, обновление страницы, возврат и переключение учеников сохраняют корректный контекст.
- [ ] На 360 px нет горизонтальной прокрутки страницы, график работает касанием и клавиатурой.
- [ ] Unit-тесты проверяют агрегацию и крайние случаи; E2E проверяет путь от профиля до упражнения и обратно, фильтры и появление нового результата после завершения занятия.
- [ ] Перед слиянием проходят `npm test`, `npm run lint`, `npm run typecheck`, `npm run test:e2e` (последняя команда также собирает production-версию).

## Решение для обсуждения

Рекомендуемый старт: таблица по умолчанию, график второй вкладкой, последние 90 дней. После просмотра тренером можно скорректировать приоритеты, не меняя принцип хранения исторических результатов.
