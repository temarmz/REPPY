## Исправления по рабочей проверке

Пользователь сообщил об отсутствии упражнений/прогресса и показал сообщение «отменено». В планировщике обновлений новое событие Realtime отменяло reloadTask, в том числе уже исполнявший запросы снимка. URLSession при такой отмене возвращает URLError.cancelled; прежняя проверка скрывала только Swift CancellationError. В результате внутреннее прерывание показывалось красной ошибкой и могло мешать загрузке данных.

События теперь объединяются: текущий запрос не отменяется новым событием, после него выполняется необходимое следующее обновление. Планировщик различает ожидающий таймер и активное чтение; завершение старого задания не очищает новое. Фоновая отмена остаётся допустимой, запрос сохраняется для следующего foreground. Обе формы системной отмены не показываются как ошибка. После прерывания первоначальной загрузки текущий аккаунт получает повторное чтение, без автоматического повтора команд записи. Повторная загрузка также восстанавливает Realtime, если наблюдатель ещё не был запущен.

После исправления отмены отсутствие данных сохранилось. Временная диагностика, содержащая только количества и логические флаги без содержимого записей, подтвердила успешную загрузку снимка. Причина оказалась отдельной: iOS выбирала первую связь ученика с тренером, а в ней не было тренировок. Веб связывает назначения с самим учеником и показывает данные всех его разрешённых связей. Главная, календарь, история, прогресс и абонемент iOS переведены на множество связей аккаунта, без выбора первой и без включения других учеников. Прогресс одинакового упражнения объединяется по собственным завершённым занятиям, а контекст тренера по-прежнему ограничен выбранной связью.

Пользователь подтвердил появление упражнений и прогресса на iPhone после обновления. Временный код диагностики убран; личные записи, идентификаторы аккаунта и агрегаты рабочего профиля не включены в репозиторий.

В дневнике добавлена проверка владельца сессии перед запросами и после ответов. Остановленный NotesStore не сохраняет старые черновики с токеном нового аккаунта и не удаляет неподтверждённый черновик из-за позднего ответа. Старый pending mutation сохраняется для идемпотентного восстановления своего аккаунта. Ручное разрешение конфликтов и серверные RPC сохранены.

Добавлена команда `npm run ios:doctor`: проверяет URL, согласованность локальных публичных настроек, подпись сборки и публичный Telegram-config; `--offline` пропускает сеть. Диагностика не выводит ключи и не читает сессии пользователей.

## Ограничения и продолжение

На этом Mac запрос к тому же публичному endpoint проходит из Node и macOS Foundation, но в Simulator iOS 18.3.1 и 26.5 воспроизводится NSURLErrorDomain -1003. Независимая программа Foundation внутри Simulator также воспроизвела ошибку без участия кода REPPY. Первопричина сети окружения не установлена; DNS, proxy, VPN и защитные настройки Mac не менялись. Для рабочего OAuth использован подключённый iPhone.

Вход, чтение веб-заметок и появление упражнений/прогресса подтверждены пользователем на iPhone. Реальная запись/воспроизведение видео, RLS двух разных пользователей, регистрация и приглашение, истечение токена/подписанного URL и конфликты между вебом и iOS на рабочих аккаунтах не считаются пройденными синтетическими тестами. Изолированный backend suite не запускался: Docker daemon не работает, preview/admin-конфигурации нет. Защита запрета запуска такого suite против production сохранена.
