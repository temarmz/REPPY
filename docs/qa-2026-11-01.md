## Подтверждённые проблемы

Два дефекта сохранности заметок из незамерженного #21 воспроизведены заново против кода текущего main: запоздалый ответ откатывает уже подтверждённую revision/текст, повреждённый черновик удаляется при загрузке. Три регрессионных сценария красные, восемь контрольных прошли. В обновлённом PR остаются прежние сфокусированные исправления и тесты; повторная независимая реализация не создавалась.

Установлена причина части нестабильных падений quality gate. На чистом main во время page-fade-in реальная кнопка календаря с CSS height=44px и width=44px возвращала height=43.99993896484375 через getBoundingClientRect; transform родительского main был matrix(1,0,0,1,0,8.50411), затем 6.35532. После анимации отклонение исчезает. Это ошибка момента измерения аудита, а не доказанный дефект размера контрола.

Аудит теперь ожидает завершение конечных анимаций активного main и выполняет прежние измерения/проверки 44x44 и перекрытий. Числовой допуск не добавлен, assertions не ослаблены, анимации приложения не отключены. Новый positive/negative тест требует завершившуюся анимацию и отклоняет реальную кнопку шириной 43px.

Регрессия повреждённого черновика обновлена под текущий контракт UI: вместо удалённого текста «Сохранено» ожидается реальная запись нужного текста/даты в основном demo-репозитории, пустой статус, сохранённое предупреждение и неизменённая повреждённая копия. Reload подтверждает восстановление новой записи. Это не замена продуктовой логики ради теста.
