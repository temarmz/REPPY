# Создание и совместное выполнение тренировок

Проверка по результатам тестирования 5 ноября 2026 года.

## Найденные причины

Нативный редактор разрешал сохранить назначение без упражнений и прямо предлагал заполнить его позже. Сохранение создавало обычное назначение, доступное ученику. База проверяла наличие массива `exercises`, но допускала пустой массив. RPC старта создавал сессию отдельной транзакцией; последующий `save_session_progress` отвергал пустой план. Поэтому после ошибки оставалась сессия, которую интерфейс предлагал продолжить.

Веб сохранял полный снимок плана и результатов с одной ревизией. Независимые изменения разных участников получали конфликт. Нативное восстановление умело объединять результаты только при полностью одинаковом плане, поэтому комментарий к упражнению блокировал такое восстановление.

Hosted-проверка воспроизвела отдельную серверную причину бесконечного сохранения: пользовательский конфликт возвращал SQLSTATE `40001`, который PostgREST 14 бесконечно повторяет как транзакционную ошибку. Исправление возвращает `PT409` (HTTP 409) для CAS-конфликтов тренировок, заметок, платежей и приглашений; оба клиента сохраняют совместимость со старым кодом. Подтверждение: [Supabase troubleshooting](https://supabase.com/kb/troubleshooting/high-cpu-and-infinite-transaction-retries-when-using-custom-error-codes-in-rpc-functions).

При повторной проверке 6 ноября доступ через Supabase CLI восстановлен. Среди текущих неудалённых назначений за 5 ноября одинаковых названия, связи, даты и времени не найдено; это не исключает ранее удалённые дубли. В iOS проверка некорректных подходов выполнялась **до** вставки назначения; гипотеза о частичной вставке именно после такой ошибки не подтверждена. Пустой план при этом считался допустимым.

## Изменения

- Пустой план и незаполненные/некорректные подходы не назначаются. Ошибка формы сохраняет черновик. Нулевой вес допустим. Упражнения без заранее заданных подходов остаются допустимыми по существующему контракту.
- Новый веб-черновик хранит стабильный UUID назначения. Повторная отправка, включая восстановление репозитория после потерянного ответа, использует тот же ID. Проверка плана выполняется до изменения локального календаря и до обращения к базе.
- Серверные триггеры проверяют снимок при публикации/редактировании назначения и до создания сессии обоими RPC старта. Они проверяют идентификаторы, доступность упражнений, повторы и вес. Существующие записи миграция не удаляет.
- Веб и iOS скрывают от ученика старые пустые активные назначения и сессии. У тренера они остаются доступны для исправления.
- Независимые изменения объединяются относительно подтверждённой исходной версии по полям, упражнениям и подходам. Служебная дата изменения не создаёт конфликт. Удаление не может молча уничтожить одновременно отредактированное упражнение.
- Следующая локальная запись сохраняет уже объединённые удалённые правки, включая изменения, введённые во время предыдущего сохранения.
- Старт создаёт сессию и исходные подходы одной транзакцией. Второй клиент получает ту же сессию; старт не перезаписывает выполненные подходы. Старая пустая активная сессия без результатов восстанавливается из готового назначения при явном старте. Если результаты уже есть, требуется явное восстановление.
- Потеря ответа одновременно с независимой правкой тренера также допускает объединение.
- Default privileges схемы `public` приведены к приватным значениям, предусмотренным исходной схемой. Существующие явные API-права не меняются.
- Разные изменения одного поля требуют явного восстановления. Автоматические попытки ограничены; ошибка переводит сохранение в состояние ошибки.
- После успешной веб-записи перечитывается актуальный снимок. В iOS недоступная кнопка действия формы использует общий нейтральный фон.

## Проверки

- `npm test`: 234 проверки.
- `npm run typecheck`, `npm run lint`, `npm run build:pages`: успешно.
- Полный Playwright: 556 проверок. Включены обе роли, темы, 360/390 px, desktop и WebKit.
- Swift portable tests: 56 проверок успешно до дополнительного теста даты изменения. Полный актуальный набор затем выполнен XCTest на iPhone Simulator: 66 проверок успешно.
- UI-тест iOS проверяет запрет назначения именованного пустого плана в обеих темах; снимки проверены вручную.
- SQL-регрессии: 15 наборов, 231 утверждение прошли в отдельном hosted-проекте `reppy-preview-ci`, с rollback каждой проверки; CI повторяет их в чистом локальном Supabase.
- `ios:check` проходит. Рекомендуемые настройки Xcode перенесены в генератор; семантическое сравнение подтвердило сохранение существовавших настроек проекта.
