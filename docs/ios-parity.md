# Перенос REPPY на iOS

Согласовано 29 октября 2026: нативные Swift/SwiftUI, только iPhone, iOS 18+, Telegram и общий Supabase, первый этап — локальный запуск. Web и iOS развиваются в одном репозитории.

## Приёмка

Полной копией считаем клиент только после сборки современным Xcode и проверки обеих ролей на iOS 18 с теми же серверными аккаунтами, которыми пользуется веб. Реализация экранов в исходниках сама по себе не закрывает этот критерий.

| Сценарий | Нативная реализация | Что нужно проверить на устройстве |
| --- | --- | --- |
| Telegram, вход существующего аккаунта, новый тренер | `Data/TelegramAuthorization`, `App/AppStore`, `SignInScreen` | Регистрация `reppy://auth/telegram` в BotFather и публикация серверной allowlist; возврат из Telegram/Safari, отмена, nonce/state/PKCE, истёкший вход |
| Приглашение ученика | `StudentsScreen`, `SignInScreen` | Новый/существующий ученик, истечение/отзыв токена; открытие через вставленную веб-ссылку |
| Расписание и перенос | `CalendarScreen`, `AssignmentScreen` | Дата и время локальные, онлайн без времени, запрос ученика и решение в вебе |
| План и повтор | `AssignmentEditorScreen` | Изоляция снимков, UUID упражнений, длинные планы, клавиатура и черновик |
| Видеоинструкции | `ExerciseEditorCard`, `InstructionScreen` | Выбор файла, лимит 100 МБ, Storage RLS, воспроизведение, закрытие формы во время загрузки |
| Выполнение | `ActiveWorkoutScreen` | Вес с запятой, свой вес, длительность, пропуск подходов, смена структуры, таймер, завершение процесса |
| Списание и возврат | Существующие RPC через `AppStore+Commands` | Повтор завершения после потери ответа, без двойного списания; удаление в другом клиенте |
| Абонементы | `SubscriptionsScreen` | Изменение/удаление оплаты и конфликты, долг, скрытый финансовый журнал у ученика |
| Прогресс и история | `HistoryScreen`, `SessionResultScreen` | Сравнение цифр с вебом, фильтры периода, раздельные режимы веса/повторов/длительности |

| Дизайн | `UI`, `DesignKitScreen` | Две темы, узкие iPhone, Dynamic Type, VoiceOver, safe area, клавиатура, окна и ошибки |

## Подтверждённые проверки

- 42 переносимых XCTest: исходные проверки данных, дат и прогрессии плюс HTTP-запросы и ошибки, публичная конфигурация и сроки входа, защищённые от перезаписи черновики, координация обновлений и сохранение выполненных подходов. Сырые значения полей профиля переживают восстановление; валидация роста/веса соответствует вебу и SQL-ограничениям.
- Восемь сценариев изменения активной тренировки получают ожидаемые снимки и результаты непосредственно от `updateSessionWorkout` / `workoutFromSession` веб-версии. Swift сохраняет выполненные упражнения/подходы при изменении структуры и повторяет фактические значения завершённых подходов.
- Детерминированная проверка Swift-токенов и тестовых данных по веб-источнику, структуры Xcode-проекта и plist.
- XCTest UI smoke-сценарии добавлены для обеих ролей и тем. **Локально не запускались:** Intel Mac с Tahoe и Xcode 12.5 / SDK 14.5. Пользователь рассматривает перенос на M4; альтернативный путь — уже подготовленная сборка GitHub Actions на macOS.

## Открытые пункты до признания полного паритета

- Сборка и исправление диагностик современного компилятора; UI-прогон и визуальная проверка.
- Пользователь добавил `reppy://auth/telegram` в BotFather. Подготовленная серверная allowlist ещё не опубликована. Trusted Origins для веб-виджета — `https://temarmz.github.io`, без пути.
- Интеграционная проверка двух реальных аккаунтов и изменений с веба. В production данные при разработке не изменялись.
- Универсальные ссылки приглашений потребуют домена с AASA; пока поддержаны вставка текущей веб-ссылки и локальная схема `reppy://invite?token=...`.
- Запись видео камерой, предварительная проверка приглашения, сверка записей после потери HTTP-ответа и восстановление черновиков плана, выполнения, личных данных, оплат, упражнений и обратной связи реализованы; требуют интеграционных проверок.
- Push/APNs, HealthKit, Apple Watch и TestFlight не входят в согласованный первый этап; текущие уведомления остаются в Telegram.

## Порядок изменений

Меняем бизнес-правило → обновляем общий сервер и его проверки → добавляем один и тот же сценарий в web/iOS → обновляем контракт и тесты → принимаем обе версии. Цвета и размеры меняем в `app/ui/tokens.css`, затем `npm run ios:sync`. Нативные составные компоненты меняем в `ios/REPPY/UI`, с каталогом и дизайн-китом.
