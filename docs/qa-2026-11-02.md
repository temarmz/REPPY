## Исправлено

### Нативный Node ESM не мог загрузить диагностику

Новый импорт `./activity-log` в persistence-diagnostics.ts не содержал расширение. Vite собирал веб, но штатный `npm test` использует Node strip-types без bundler resolution. Из-за импорта не запускались проверки очереди сохранения, revision, профиля, удаления платежей и Supabase-репозитория.

Добавлено только `.ts` к импорту, по существующему паттерну Node-совместимых модулей проекта. После правки все 26 unit-файлов прошли. Assertions/runner/версии зависимостей не менялись; пять ранее красных существующих файлов служат регрессионной проверкой этого import graph.

### Устаревший тест выхода обходил подтверждение

CI показывал calls=0 вместо calls=1 у 20 случаев выхода тренера/ученика. Свежий локальный сценарий trainer/dark/320 воспроизвёл сбой. Реальный экран уже намеренно открывает ConfirmationModal «Выйти из аккаунта?»: до подтверждения запрос не должен отправляться. Это не продуктовый дефект выхода.

Тест теперь проверяет, что открытие/отмена окна не вызывает signOut, затем подтверждает выход. После сетевой ошибки он сохраняет исходные проверки доступности, фокуса, текста ошибки, повтора с клавиатуры, disabled/loading, отсутствия двойного запроса и успешного завершения. Повтор также проходит через подтверждение. Missing-profile сохраняет прямой выход. Исходные проверки не удалены и не ослаблены; добавлена проверка отмены. Узкий сценарий после правки прошёл.
