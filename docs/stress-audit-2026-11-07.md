# Стресс-проверка iOS и веба — 7 ноября 2026

## Среда и безопасность

Проверка выполнялась на отдельном hosted-проекте `reppy-preview-ci`, а также локально в Chromium/WebKit и iPhone Simulator. Production Supabase не использовался. Драйвер сверяет фиксированный project ref и имя preview через management API, создаёт временные аккаунты и удаляет только известные ему UUID. Секрет service role остаётся в Node-процессе; Swift получает только публичный ключ и сессию временного пользователя через файл с правами 0600, удаляемый после прогона.

## Найденные дефекты и изменения

### Неполный снимок веб-аккаунта

На 100 учениках и 3600 назначениях веб загружал ровно 1000 назначений без ошибки; Swift-загрузчик получал все 3600. Причина — серверный предел одной выдачи PostgREST и отсутствие пагинации в веб-репозитории.

Теперь все коллекции веб-снимка читаются страницами по 1000 строк со стабильным порядком. Для подходов используется составной порядок `(session_id, exercise_instance_id, set_number)`. Журнал тренера, возвращаемый RPC, тоже пагинируется; в iOS он переведён на существующий постраничный `rows`. Ошибка поздней страницы, включая журнал, отклоняет весь снимок вместо частичной истории или ложного пустого баланса. Ревизии принимаются только после успешной сборки снимка, как и раньше.

Регрессии проверяют 2105 строк таблицы и RPC, стабильный порядок, уникальность и отказ при ошибке второй страницы. Живой прогон дополнительно проверяет 3600 назначений и 1205 записей журнала реальными `createSupabaseRepository` и `AppSnapshotLoader`/`SupabaseAPI`.

### Избыточные изменения browser history

На синтетическом потоке сотен мгновенных переходов WebKit выбрасывает `SecurityError`: более 100 изменений History API за 10 секунд. Добавлен пропуск `replaceState`, если URL и состояние уже совпадают: два события одного перехода больше не вызывают одинаковые записи. Обновление изменённого состояния и URL сохранено, ошибки браузера не подавляются.

Это не отменяет системный лимит Safari. Предельно быстрый непейсированный сценарий остаётся известной границей, а не объявляется исправленным полностью. Длительная проверка проходит с интервалом 250 мс между маршрутами и настоящей прокруткой `.page-wrap`.

### Надёжность нативных UI-тестов

В нескольких сценариях остались старые обращения к «Отмена» и сокращённой подписи инструкции. У формы добавлен стабильный `form-cancel`; поиск инструкции учитывает название упражнения в подписи. В графике стрелки получили уникальные идентификаторы. На SE тест считал перекрытую нижним таббаром стрелку hittable и нажимал «Главная»: теперь перед нажатием проверяется её положение над таббаром. При замене числа в платёжной форме тест ставит курсор в конец значения перед удалением, чтобы проверять именно `0`, а не результат вставки в середину.

Проверки сохранения/отмены, конфликтов, баланса и восстановления не удалены и не ослаблены.

Для межплатформенной гонки чередуется задержка JavaScript, чтобы проверить победу обеих сторон, а не только клиента с более быстрым соединением. Это конкурентные CAS-запросы с общей исходной ревизией, включая управляемое опоздание одного клиента.

## Результаты и интерпретация

- Живой preview: оба загрузчика читают 3600/3600 назначений и 1205/1205 записей журнала. После завершения оба видят баланс 1204, 200 подходов и одну завершённую сессию. 20/20 гонок имеют одного победителя (10 Swift, 10 JavaScript), остальные 160 запросов получают конфликт. Потерянная квитанция не вызывает второго повышения ревизии; временные данные очищены (`cleanup: true`).
- Основной веб-набор после исправлений: **560/560**. Модульные проверки: **238/238**, включая новые регрессии пагинации и истории. Lint, typecheck, iOS contract check и веб-сборка проходят.
- iOS: первый полный прогон дал 66 успешных нативных проверок и 16/26 UI. Десять старых UI-сценариев остановились на неактуальных селекторах, скрытых поиском toolbar-действиях или неверной подготовке ввода. Все десять повторены после исправления тестов; они прошли. Дополнительно прошёл стресс большого графика на SE. Совокупный итог по последним результатам каждого сценария — **93/93** (66 нативных, 26 smoke, один стресс). Это совокупность целевых прогонов, а не утверждение о едином зелёном полном прогоне; источники записаны в `native-summary.json`.
- У 1320 переходов с паузой 250 мс получены 8/8 успешных browser soak-сценариев. Измеряется появление активного маршрута без учёта заданной паузы; это локальная синтетическая метрика, не SLA и не измерение времени от касания на физическом устройстве.
- Непейсированный вариант превышает лимит WebKit. Его падение сохранено как известная граница. Ещё один повторный full-web запуск потерял сервер, принадлежавший параллельному soak: stress теперь использует отдельный порт 4183, а финальный full-web прогон на 4173 завершился успешно.

## Воспроизведение

```sh
# Нужны Supabase CLI management-доступ, macOS/Xcode. Target зафиксирован в драйвере.
npm run test:stress:preview

# Локальный веб build должен быть актуальным. Отдельный порт 4183.
npm run build:pages
REPPY_SOAK_ROUNDS=30 npm run test:stress:web

# Реальная атомарная запись файлов, без сети и аккаунтов Supabase.
npm run test:stress:drafts
```

`REPPY_SOAK_ROUNDS` по умолчанию 10, максимум 10000. `REPPY_SOAK_INTERVAL_MS` по умолчанию 250; значение 0 воспроизводит экстремальный поток и лимит WebKit. Для многочасового прогона число кругов нужно увеличить; этот аудит не выдаёт несколько минут за несколько часов.

Метрики, JSON-отчёты, видео/трассы браузеров и журналы находятся в `work/stress-2026-11-07/` (не включаются в Git). `preview-before.json` фиксирует исходное усечение; `preview-stress.json` — результат последнего запуска и статус очистки. `native-draft-chaos.json` — результат 30 убийств процесса. Для browser soak метрики p50/p95/max и heap при доступности приложены к каждому тесту в JSON-отчёте.

## Границы доказанного

- Browser soak работает с демо; отключение сети в нём проверяет доступность локального интерфейса, а не серверную очередь. Серверные гонки и потеря ответа проверены отдельно реальными клиентами; очередь, отмена, истечение сессии и поздние ответы — существующими web/Swift-тестами с управляемым транспортом.
- Swift preview probe использует настоящие исходники iOS API и загрузчика, скомпилированные для macOS. Отрисовка и UI-переходы отдельно проверяются в iPhone Simulator; это не одновременное управление двумя живыми UI над preview.
- SIGKILL-проба использует тот же `FileDraftStore` на macOS. Она не заменяет проверку iOS Data Protection на заблокированном физическом устройстве.
- Не проверены реальные Telegram OAuth, камера/Storage, системные push, поведение физического устройства при memory pressure и многочасовая деградация. Системный предел History API при экстремальной частоте остаётся известной границей.
