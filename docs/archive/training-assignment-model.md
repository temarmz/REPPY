# ТЗ: Шаблоны, назначения и персональные версии тренировок

> Статус: выполнено и опубликовано 31 августа 2026 года.
> Основная реализация: `a470227`; исправление метаданных расписания: `925a7ca`.
> Оставшиеся продуктовые идеи вынесены в [`../backlog.md`](../backlog.md).

## Контекст

В текущем прототипе REPPY данные хранятся в `localStorage`, а основная логика лежит в:

- `app/reppy-data.ts`
- `app/reppy-app.tsx`

Сейчас уже есть три важные сущности:

- `Workout` - шаблон тренировки, который создает тренер.
- `Assignment` - назначение тренировки конкретному ученику на дату и время.
- `WorkoutSession` - факт выполнения тренировки учеником.

Важная находка: сейчас `Assignment` хранит только `workoutId`, то есть ссылку на шаблон тренировки. Само содержимое тренировки в назначение не копируется.

Из-за этого появляется риск: если тренер позже отредактирует шаблон, уже назначенные тренировки могут начать показывать новую версию. Для реального продукта это плохая логика, потому что назначенная тренировка должна быть стабильной.

## Цель

Сделать модель тренировок понятной и безопасной:

1. Тренер создает переиспользуемый шаблон тренировки.
2. Тренер назначает тренировку ученику.
3. В момент назначения создается независимая копия тренировки.
4. Тренер может изменить назначенную тренировку под конкретного ученика.
5. Тренер может сохранить эту измененную версию для этого ученика, чтобы в следующий раз назначать ее быстрее.
6. История выполненных тренировок не должна меняться, если шаблон был отредактирован позже.

## Главное продуктовое правило

Шаблон тренировки - это стартовая заготовка, а не постоянный источник правды для уже назначенных тренировок.

После назначения тренировка должна жить как отдельная копия внутри назначения.

Простыми словами:

- Редактирование шаблона влияет только на будущие назначения.
- Редактирование назначенной тренировки влияет только на это назначение.
- Если тренер хочет, он может сохранить правки как персональную версию для конкретного ученика.
- Выполненная тренировка всегда должна показывать то, что ученик реально выполнял.

## Текущая проблема

Сейчас логика выглядит так:

```text
Workout
  -> Assignment хранит workoutId
  -> ученик видит тренировку через связанный Workout
```

Проблема:

```text
Тренер редактирует Workout
  -> назначенные тренировки с этим workoutId тоже могут визуально измениться
```

Это создает путаницу:

- тренер может думать, что меняет только шаблон;
- ученик может увидеть измененную тренировку без нового назначения;
- история может стать недостоверной;
- нельзя безопасно адаптировать тренировку под одного ученика.

## Целевая модель

Рекомендуемая модель:

```text
Workout template
  -> Assignment with workout snapshot
  -> WorkoutSession with workout snapshot

Student workout version
  -> сохраненная персональная версия шаблона для конкретного ученика
```

Для текущего прототипа можно сохранить существующие названия типов, но расширить их.

## Изменения в данных

### 1. Workout

`Workout` остается переиспользуемым шаблоном тренера.

```ts
export type Workout = {
  id: string;
  name: string;
  exercises: WorkoutExercise[];
  createdAt: string;
  updatedAt?: string;
};
```

### 2. Assignment

В `Assignment` нужно добавить копию тренировки.

```ts
export type Assignment = {
  id: string;
  workoutId: string;
  studentId: string;
  assignedAt: string;
  scheduledFor: string;
  scheduledTime: string;
  status: 'assigned' | 'completed';
  workoutSnapshot: Workout;
  source: 'template' | 'student-version' | 'manual-edit';
  rescheduleRequest?: {
    scheduledFor: string;
    scheduledTime: string;
    requestedAt: string;
  };
};
```

Правила:

- `workoutId` хранит связь с оригинальным шаблоном.
- `workoutSnapshot` хранит конкретную тренировку, которую увидит ученик.
- Экраны назначения и ученика должны читать данные из `assignment.workoutSnapshot`.
- Старые назначения без `workoutSnapshot` нужно мигрировать: взять текущий связанный `Workout` и скопировать его внутрь назначения.

### 3. StudentWorkoutVersion

Нужно добавить новую сущность: персональная версия тренировки для ученика.

```ts
export type StudentWorkoutVersion = {
  id: string;
  studentId: string;
  baseWorkoutId: string;
  name: string;
  exercises: WorkoutExercise[];
  createdAt: string;
  updatedAt: string;
};
```

Добавить в `DemoState`:

```ts
export type DemoState = {
  loggedIn: boolean;
  role: Role;
  activeStudentId: string;
  students: Student[];
  workouts: Workout[];
  studentWorkoutVersions: StudentWorkoutVersion[];
  assignments: Assignment[];
  sessions: WorkoutSession[];
};
```

## Логика назначения

### Сейчас

```text
Тренер открывает шаблон
Тренер нажимает "Назначить"
Выбирает ученика, дату и время
Создается Assignment с workoutId
```

### Нужно

```text
Тренер открывает шаблон
Тренер нажимает "Назначить"
Выбирает ученика, дату и время
Система проверяет, есть ли персональная версия этого шаблона для ученика
Создается Assignment с workoutSnapshot
```

Правило выбора версии:

1. Если для `studentId + baseWorkoutId` есть `StudentWorkoutVersion`, использовать ее.
2. Если персональной версии нет, использовать обычный шаблон `Workout`.
3. После создания назначения тренер может дополнительно отредактировать назначенную тренировку.

## Логика редактирования

### 1. Редактирование шаблона

Путь:

```text
/trainer/workouts/:id/edit
```

Поведение:

- меняет только шаблон в `workouts`;
- не меняет уже созданные назначения;
- не меняет завершенные тренировки;
- влияет только на будущие назначения, где нет персональной версии ученика.

Рекомендуемый текст в UI:

```text
Изменения повлияют только на будущие назначения. Уже назначенные тренировки останутся без изменений.
```

### 2. Редактирование назначения

Сейчас экран редактирования назначения меняет только дату и время.

Путь:

```text
/trainer/assignments/:id/edit
```

Нужно дать тренеру возможность редактировать:

- дату;
- время;
- упражнения;
- количество подходов;
- плановые повторы;
- плановый вес.

Эти правки должны менять только `assignment.workoutSnapshot`.

Оригинальный шаблон `Workout` не должен изменяться.

### 3. Сохранение версии для ученика

После редактирования назначенной тренировки добавить выбор:

```text
Сохранить только это назначение
Использовать эту версию для ученика в следующий раз
```

Рекомендуемый UI:

- основная кнопка: `Сохранить назначение`;
- чекбокс или тумблер: `Использовать эту версию для ученика в следующий раз`.

Если тумблер выключен:

```text
Обновляется только текущий Assignment.
source = 'manual-edit'
```

Если тумблер включен:

```text
Обновляется текущий Assignment.
Создается или обновляется StudentWorkoutVersion для studentId + baseWorkoutId.
source = 'student-version'
```

Это решает важный кейс:

```text
Тренер изменил "Ноги" для Артема.
В следующий раз при назначении "Ноги" Артему REPPY сразу предложит версию Артема.
Мария и Антон при этом не получат изменения Артема.
```

## Что должен видеть ученик

Ученик всегда видит `assignment.workoutSnapshot`.

Для ученика неважно, откуда тренировка появилась:

- из общего шаблона;
- из персональной версии;
- из ручной правки назначения.

Для него это просто назначенная тренировка.

## История выполненных тренировок

Когда ученик начинает тренировку, `WorkoutSession` тоже должна сохранить копию тренировки.

```ts
export type WorkoutSession = {
  id: string;
  assignmentId: string;
  studentId: string;
  workoutId: string;
  workoutSnapshot: Workout;
  startedAt: string;
  completedAt?: string;
  mood?: MoodRating;
  comment?: string;
  results: SetResult[];
};
```

Зачем:

- история остается честной;
- тренер может редактировать шаблон позже, но старые результаты не поменяются;
- если назначение изменили после старта сессии, начатая сессия не ломается.

## Acceptance Criteria

### Редактирование шаблона

- Тренер редактирует шаблон `Ноги`.
- Уже назначенные тренировки `Ноги` не меняются.
- Новые назначения используют обновленный шаблон, если у ученика нет персональной версии.

### Редактирование назначения

- Тренер открывает назначенную тренировку Артема.
- Тренер меняет вес, повторы или упражнения.
- Артем видит измененную тренировку.
- Оригинальный шаблон не меняется.

### Сохранение версии для ученика

- Тренер редактирует назначенную тренировку Артема.
- Тренер включает `Использовать эту версию для ученика в следующий раз`.
- Позже тренер снова назначает этот же шаблон Артему.
- REPPY использует сохраненную версию Артема.
- Другие ученики не получают изменения Артема.

### История

- Ученик завершает тренировку.
- Тренер позже меняет шаблон.
- Завершенная тренировка в истории остается такой, какой была в момент выполнения.

### Старые демо-данные

- Старый `localStorage` не ломает приложение.
- Старые назначения автоматически получают `workoutSnapshot`.

## Что еще стоит улучшить

### 1. Разделить слова в интерфейсе

Сейчас слово “тренировка” может означать разные вещи.

Лучше использовать:

- `Шаблон` - переиспользуемая заготовка.
- `Назначение` - тренировка в расписании ученика.
- `Результат` - выполненная тренировка.
- `Версия для ученика` - персональная адаптация шаблона.

### 2. Добавить явное предупреждение при редактировании шаблона

Тренеру нужно понимать, что он меняет не конкретного ученика, а базовую заготовку.

Текст:

```text
Ты редактируешь шаблон. Уже назначенные тренировки не изменятся.
```

### 3. Добавить быстрый вход в персональную правку

На экране ученика рядом с назначенной тренировкой можно дать действие:

```text
Адаптировать под ученика
```

Это лучше, чем заставлять тренера идти через общий список шаблонов.

### 4. Добавить “создать на основе”

Для шаблонов:

```text
Дублировать шаблон
```

Для назначений:

```text
Создать шаблон из этого назначения
```

Это поможет тренеру быстро превращать удачные разовые правки в новые шаблоны.

### 5. Добавить индикатор источника

В деталях назначения можно показывать маленький статус:

```text
Основано на шаблоне “Ноги”
```

или

```text
Персональная версия Артема
```

Это снизит путаницу.

## Будущая backend-модель

Для реального backend лучше разделить таблицы так:

```text
workout_templates
workout_template_exercises
workout_assignments
workout_assignment_exercises
student_workout_versions
student_workout_version_exercises
workout_sessions
workout_session_results
```

Главное правило для backend:

- шаблон - это заготовка;
- назначение - это плановая копия;
- сессия - это исторический факт.

Так продукт будет вести себя предсказуемо и не будет случайно менять старые или уже назначенные тренировки.
