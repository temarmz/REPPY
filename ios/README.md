# REPPY для iPhone

Нативный клиент на Swift / SwiftUI. Минимальная версия — **iOS 18.0**, семейство устройств — **только iPhone**. Веб и iOS остаются в одном репозитории, используют одни аккаунты Telegram, Supabase, серверные права и транзакционные RPC.

## Локальный запуск

Нужен Xcode 16 или новее с iPhone Simulator. Установленный на момент создания проекта Xcode 12.5 не умеет собирать и запускать этот клиент.

Сам iPhone может запускать подписанную сборку, но не заменяет Mac с Xcode. Для локальной разработки подходит Mac с M4 и совместимой версией Xcode для установленной Tahoe. Минимальную iOS приложения при этом оставляем 18.0. Альтернатива — сборка и XCTest на macOS runner в GitHub Actions; workflow `REPPY iOS` уже подготовлен. Его simulator-сборка не требует Apple Developer Team и не устанавливается на физический iPhone. Для установки на устройство нужна отдельная подписанная сборка.

```sh
# Из корня репозитория. Копируются только публичные параметры подключения.
python3 ios/scripts/configure.py

# Открыть проект, выбрать схему REPPY и iPhone с iOS 18+.
open ios/REPPY.xcodeproj
```

Конфигурация уже создана локально, если в веб-проекте были корректные публичные параметры. Повторный запуск `configure.py` сохраняет существующий файл. Ручная настройка: скопировать `Config/Local.example.xcconfig` в `Config/Local.xcconfig`. Для симулятора Apple Developer не нужен. Для своего iPhone указать команду подписи в Xcode или `DEVELOPMENT_TEAM` и свой Bundle ID в локальной конфигурации. Пароли и private/service-role ключи приложению не нужны.

Первый экран позволяет войти в существующий аккаунт через Telegram либо открыть изолированное демо любой роли. Демо переносит даты относительно текущего дня и не обращается к рабочему backend. Для UI-тестов: launch arguments `--demo-trainer` или `--demo-student`, оформление `-appearance light` / `-appearance dark`.

## Что перенесено в исходники

- Вход и создание кабинета тренера через Telegram; принятие приглашения по вставленной веб-ссылке или токену; общие аккаунты с вебом.
- Обе роли, главная, календарь, список и профиль ученика, редактирование личных данных, системная/светлая/тёмная тема.
- Назначение, редактирование, повтор и удаление тренировок; очный и онлайн-формат; запрос и решение по переносу.
- Библиотека и собственные упражнения, наборы подходов, внешний/собственный вес, повторения/длительность, порядок и замена упражнений, текст, запись и загрузка видеоинструкций.
- Выполнение с таймером, фактическими значениями и отметками, локальным черновиком и сохранением с проверкой версии; завершение и выбор списания тренером; отзыв ученика.
- История, результаты, прогресс по упражнениям и графики, абонементы и журнал, добавление/изменение/удаление пополнений и удаление абонемента.
- Подключение уведомлений Telegram, Realtime и обновление при возврате в приложение; защищённое хранение входа и изоляция черновиков по аккаунтам.

Облачная сборка SwiftUI в Xcode 16.4 и smoke-прогон на iPhone 16 Pro / iOS 18.5 прошли: 42 модульных теста и 2 UI-сценария с обеими ролями и темами. **Полная функциональная эквивалентность ещё не подтверждена:** остаются реальные Telegram-аккаунты, совместная работа двух клиентов и расширенная проверка интерфейса. Матрица и открытые пункты — в [docs/ios-parity.md](../docs/ios-parity.md).

## Структура и совместное развитие

`REPPY/Core` — переносимые Codable-модели и вычисления. `Data` — Auth, PostgREST/RPC/Storage, Realtime, защищённые черновики. `App` — жизненный цикл и состояние аккаунта. `Features` — сценарии и экраны. `UI` — общая нативная библиотека.

Снимки тренировок используют camelCase веб-версии. Строки таблиц используют snake_case существующей схемы. Нативный клиент не требует миграций базы. Вход использует системный `ASWebAuthenticationSession`, отдельный callback `reppy://auth/telegram`, PKCE, state и nonce; обмен кода и проверку подписи выполняет существующий `telegram-auth`.

В BotFather используются разные значения:

| Поле | Значение |
| --- | --- |
| Trusted Origins веб-виджета | `https://temarmz.github.io` — без пути `/REPPY/` |
| Redirect URI веба | `https://temarmz.github.io/REPPY/` |
| Redirect URI iPhone | `reppy://auth/telegram` |

Пользователь подтвердил добавление iPhone callback 29 октября 2026. В Trusted Origins схема `reppy://` не нужна: это не origin страницы с виджетом. URLSession нативного клиента не требует изменения веб-CORS.

Для рабочего входа ещё нужно опубликовать подготовленное дополнение allowlist функции `supabase/functions/telegram-auth/index.ts`. Веб-redirect сохранён. До публикации доступно локальное демо; рабочий iOS-вход покажет сообщение о ненастроенном серверном callback. HTTPS-callback вместо схемы потребует своего домена, Associated Domains и AASA/webcredentials. Вход необходимо проверить на реальном устройстве с установленным Telegram и без него.

```sh
npm run ios:sync       # Обновить Swift-токены и детерминированные демо/тестовые данные из веба
npm run ios:project    # Обновить .xcodeproj после добавления/удаления файлов
npm run ios:check      # Проверить отсутствие рассинхронизации
npm run ios:test       # Переносимые тесты Swift без iPhone Simulator
xcodebuild test -project ios/REPPY.xcodeproj -scheme REPPY \
  -destination 'platform=iOS Simulator,name=iPhone 16' CODE_SIGNING_ALLOWED=NO
```

`ios:test` автоматически выбирает SDK macOS и архитектуру Intel/Apple silicon и использует кеш внутри `ios/.build`. Поэтому доменную логику можно тестировать и на нынешнем Intel Mac со старым Xcode, пока сборка SwiftUI остаётся недоступна. На этапе рефакторинга прошли 42 таких XCTest, включая проверку восьми переходов состояния по результатам живого веб-reducer. Это не заменяет simulator/UI и сетевую проверку двух рабочих аккаунтов.

Черновики используют версионированные файлы с проверкой аккаунта и формы. Отсутствующий файл отличается от нечитабельного; повреждённая запись сохраняется и не перезаписывается автоматически. Экран предлагает явное удаление нечитабельного локального черновика. Серверные данные это действие не меняет.

Генератор Xcode-проекта использует только Python standard library; XcodeGen и сторонние Swift-пакеты не нужны. Workflow `REPPY iOS` отдельно проверяет контракт, домен, сборку и smoke-тесты обеих ролей/тем на iOS 18. Веб-публикация продолжает использовать свой существующий workflow.
