# REPPY iOS

- Нативный клиент только для iPhone, iOS 18.0+, Swift и SwiftUI. Общий backend и права — существующий Supabase; не создавай второй набор аккаунтов и бизнес-правил.
- Читай корневые `docs/design-principles.md` и `docs/component-library.md`. Для нативных экранов общая UI-библиотека находится в `REPPY/UI`; экраны в `REPPY/Features` используют её компоненты. Цвета, высоты и интервалы генерируются из `app/ui/tokens.css` командой `npm run ios:sync`. Не редактируй `Tokens.generated.swift` вручную.
- Новые общие компоненты регистрируй в `UI/Catalog.swift` и показывай в `Features/DesignKitScreen.swift`. Не добавляй локальные стили в экраны.
- Снимки плана сохраняют camelCase веб-контракта, строки PostgREST — snake_case схемы. Идентификаторы системных упражнений в рабочем режиме — серверные UUID.
- Конфликты `revision`/`updated_at` требуют явного восстановления. Не повторяй запись с новой версией без сверки содержимого. Завершение/списание/возврат выполняются существующими RPC, а не независимыми запросами клиента.
- Токены входа — только Keychain; черновики изолированы по аккаунту, файлы защищены и исключены из резервной копии. Демо не пишет в Supabase. Не включай локальную конфигурацию и секреты в Git.
- После добавления файлов запусти `npm run ios:project`. Проверки: `npm run ios:check`, `npm run ios:test`, сборка и XCTest через схему REPPY на iPhone Simulator с iOS 18+. Состояние без симуляторной сборки не считай полностью проверенным.
- Проверяй обе роли и темы, узкие iPhone, Dynamic Type, длинный текст, клавиатуру, модальные окна, пустые данные, потерю сети, истечение сессии, конфликты и восстановление после завершения процесса.
